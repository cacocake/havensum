# Expected payback tasks

The expense editor can track a partial or full expected amount with an optional person, due date and note. Reimbursements shows Awaiting paybacks, overdue tasks and history. Recording from a task opens a linked reimbursement draft with the amount and account prefilled. The existing reimbursement rules control cash and original-month net spending when the user saves that draft.

Task progress is derived from linked reimbursements through the current calendar date. Future-dated repayments reserve reimbursement capacity immediately and count toward received status on their date. This uses the existing reporting convention for received status. Editing or deleting a reimbursement can reopen an automatically resolved task. Closing a task is a metadata change. Later payment still counts as a real reimbursement and preserves closure history. The expense editor confirms closure when tracking is turned off. Confirmed expense deletion removes its task and history after linked reimbursements are resolved.

The optional `paybackTasksVersion: 1` collection is carried in full JSON backups. Older ledgers remain valid without creating tasks for past expenses. Storage and JSON import validate task data. The manual backup merge requires review for concurrent task changes, including closure versus edit or deletion. It refuses merged states with orphan tasks or expected amounts above the original expense. If transaction and task choices cannot produce a valid state, correct the source data and review again. Repeated unchanged JSON merges retain a single task. CSV import of task metadata and full-state restore are separate work, as are Android notifications.
